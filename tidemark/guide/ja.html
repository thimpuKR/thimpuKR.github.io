はじめに

Tidemark は、開発中にたまったキャッシュ・依存関係・ビルド成果物・AIモデルや、長く使っていないアプリを見つけて安全にクリーンアップする、無料のオープンソースのディスククリーンアップアプリです。スキャンは何も削除せず、クリーンアップは確認ダイアログを経た場合にのみ実行されます。

インストール

  1. Tidemark_<バージョン>_aarch64.dmg を開き、Tidemark.app を アプリケーション フォルダにドラッグします。
  2. 初回起動時に macOS が「開発元を確認できない」としてブロックした場合は、Finder でアプリを Control キーを押しながらクリック › 開く を選びます。
  3. 動作環境：Apple Silicon Mac、macOS 11 以降。

整理候補

整理候補画面では、スキャンで見つかった項目を選び、確認ダイアログを経てクリーンアップします。

スキャン

  • ヘッダーの 再スキャン はすべてを再検索します。サイドバーのカテゴリにマウスを重ねると表示される更新アイコンは、そのカテゴリだけを再検索します。
  • スキャン中は進行状況が表示され、スキャンをキャンセル で中止できます。

AIツールとモデルの整理

  • Hugging Faceは HF_HUB_CACHE → HF_HOME/hub → XDG_CACHE_HOME/huggingface/hub → 既定のパスの順に確認し、モデル・データセット・Spaceだけを表示します。共有ストレージではモデルフォルダを削除しても空き容量がほとんど増えない場合があるため、hf cache delete を推奨します。
  • Ollamaは OLLAMA_MODELS を優先します。個別のモデルは ollama rm <モデル> で削除してください。LM Studioはホームポインタ → ~/.lmstudio → 旧 ~/.cache/lm-studio の順にモデルフォルダを探します。
  • Claudeデスクトップ・WindsurfのキャッシュとWhisperモデルを個別に検出します。通常の ~/.cache 整理からLM StudioとHugging FaceのホームおよびWhisperを除外し、ログイントークンと鍵を保護します。

ブラウザーキャッシュと個人データの整理

  • Chrome・Edge・Brave・Arc・Firefox・Safari・Opera・Vivaldi はキャッシュフォルダーのみを対象にし、一般のアプリキャッシュと重複しません。Cookie・ログイン情報・履歴・ブックマーク・拡張機能のデータは保持します。実行中の警告があればブラウザーを終了してください。オフラインページは再ダウンロードが必要な場合があります。
  • Mail の添付ダウンロードコピーは 注意 項目です。メールボックス（~/Library/Mail）とサーバーの原本は保持します。コピーの編集内容は先に別の場所に保存してください。
  • iOS/iPadOS バックアップは一つずつ 危険 項目として表示し、安全な項目の選択には含めません。復元に必要な唯一のコピーかもしれないため、iCloud などの別のバックアップを確認してください。ゴミ箱を空にすると復元できません。
  • Safari・Mail・デバイスバックアップにアクセスできない場合はスキップします。必要に応じて macOS 設定でフルディスクアクセスを許可し、再スキャンしてください。

フィルタと検索

  • サイドバーで、カテゴリ、リスク、プロジェクトの未使用期間（30日・90日・180日以上）で絞り込みます。
  • リスト上部の検索欄（⌘F）は名前とパスから検索し、一致した文字を強調表示します。複数の語を入力すると、すべてを含む項目だけが残ります。Esc で消去します。
  • 安全な項目を選択 は、警告のない安全な項目だけを選択します。

詳細パネル

項目をクリックすると右側に開きます。

  • 説明と復元方法（削除後に再生成される仕組み）、クリーンアップ方法（公式コマンドまたは直接削除）を表示します。
  • フォルダの内容を展開して確認でき、削除対象には 削除 の表示が付きます。
  • Finderで表示、内蔵または外部ターミナルで開く、再計算、AIに質問 が使えます。

事前チェック

Docker の未使用データ、使用できない iOS シミュレータ、Homebrew キャッシュのようにコマンドでクリーンアップする項目は、実際に解放される容量を事前に計算します。リストには 約 13.4 GB / 合計56.4 GB のように、解放見込みと全体のサイズが併せて表示されます。

git の確認

プロジェクトフォルダ（node_modules、target など）には、git リポジトリの状態も表示されます。

  • ✓ マージ済み / リモートに保存済み：コードがリモートにあるため、クリーンアップしても安全です。
  • git の確認が必要：コミットしていない変更や、プッシュしていないコミットがあります。
  • サイドバーの リモート情報を更新（git fetch） をオンにすると、次回のスキャンからリモートブランチを最新の状態に取得してから判定します。

クリーンアップの実行

  1. 項目の前にあるチェックボックスで選択します。下部バーに選択数と解放見込みが表示されます。
  2. 必要に応じて ゴミ箱に移動 をオンにします。この場合、容量はゴミ箱を空にすると解放されます。古いファイルのクリーンアップとコマンド実行の項目はすぐに削除されます。
  3. クリーンアップ を押すと、確認ダイアログに対象の一覧が表示されます。危険な項目が含まれている場合は、同意のチェックを入れると 実行 が有効になります。
  4. 完了すると、解放した容量、ディスクの空き容量の変化、失敗した項目が概要として表示されます。

インストール済みアプリ

インストール済みアプリ画面では、長く使っていないアプリを残留ファイルまで含めて削除し、グローバルにインストールしたパッケージを管理します。アプリのスキャンはアプリ情報とこの Mac の記録だけを使い、ネットワークや AI は使いません。

アプリ一覧

  • 最終使用日には macOS の起動記録を使い、記録がない場合はアプリデータの更新日から推定します（アプリデータから推定）。
  • サイズはアプリ本体と残留ファイル（設定・キャッシュ・データ）を合計した値です。
  • ツールバーでは、未使用期間（90日・180日・1年以上）、並べ替え（サイズの大きい順 / 使っていない順）、Apple のアプリを隠す、検索を使えます。
  • 実行中 と表示されているアプリは、終了してから削除してください。

アプリと残留ファイルの削除

  1. アプリをクリックすると、詳細パネルに残留ファイルの一覧が表示されます。バンドル ID・開発元 ID が一致した項目は確実な残留ファイルで、名前だけが一致した項目は 推定 と表示されます。
  2. アプリと残留ファイルを削除 を押し、削除方法と一緒に削除する残留ファイルを選びます。推定 の項目と、他のアプリと共有している項目は、初期状態で選択から外れています。
  3. ゴミ箱に移動したアプリと残留ファイルは、ゴミ箱から元に戻せます。
削除方法 使う場面
ゴミ箱に移動（推奨） ほとんどのアプリ
Homebrew zap Homebrew cask でインストールしたアプリ。brew uninstall --cask --zap を実行した後、残った残留ファイルをゴミ箱に移動します
開発元のアンインストーラ アプリに専用のアンインストーラがある場合。削除処理はそのツールが行います

削除済みアプリの残存データ

ツールバーの削除済みアプリの残存データタブは、すでに削除したアプリが~/Libraryに残した設定・キャッシュ・コンテナをアプリ単位でまとめて表示します。

  • インストール済みアプリ（アプリ内のヘルパーを含む）、Spotlight、Homebrew cask、実行中のプロセスのいずれかが持ち主と確認できるものは表示しません。確実でない場合は表示しない側を選びます。
  • 最近30日以内に変更された項目と、Apple・共通アップデーターの項目は除外します。
  • 既定で選択されるのはキャッシュ・Webデータ・ウインドウの状態だけで、設定・コンテナは自分で選びます。自動起動項目は表示のみです。
  • ゴミ箱に移動は移動の直前に各パスを再確認し、ゴミ箱から戻せます。
  • サイズがサイズ不明 · フルディスクアクセスが必要ですと表示される場合は、フルディスクアクセス設定を開くからTidemarkを許可してください。
  • 残したいアプリは無視で一覧から外れ、下の無視を解除で再表示できます。

管理者用の削除保管庫

.pkg でインストールしたアプリや App Store から入手したアプリなど、システム（root）所有のアプリを削除するときは、macOS が管理者パスワードを求めます。

  • このようなアプリは、ゴミ箱ではなく /Library/Application Support/Tidemark Trash に移動されます。
  • 保管庫に項目があるとリストの上に案内が表示され、保管庫を空にする を押すと容量が解放されます。
  • 空にする前であれば、Finder で取り出して元に戻せます（管理者パスワードが必要）。

グローバルパッケージ

ツールバーの グローバルパッケージ タブには、Homebrew、npm・pnpm・yarn・bun のグローバル、pipx、uv tool、cargo install でインストールしたものと、npx キャッシュがまとめて表示されます。

  • アップデートを確認 は、Homebrew・npm・pnpm パッケージの新バージョンを確認します。brew update を含めてネットワークを使いますが、何も変更しません。
  • 新バージョンのみ をオンにすると、アップデートのあるパッケージだけが表示されます。
  • アップグレード（1件）または すべてアップグレード は、内蔵ターミナルで各パッケージマネージャの公式コマンドを使って実行するため、進行状況やパスワード入力を直接確認できます。メジャーバージョンが変わる場合があります。
  • パッケージの削除も、パッケージマネージャの公式コマンド（brew uninstall、npm uninstall -g など）で実行します。他のパッケージの 依存関係 としてインストールされたものは、Homebrew が削除を拒否することがあります。
  • npx キャッシュは、npx が実行時にダウンロードしておいたパッケージです。ゴミ箱に移動しても、次に npx で実行すると再ダウンロードされます。

容量マップ

容量マップは、どのフォルダが容量を占めているかを、サイズに比例した四角形（ツリーマップ）で表示します。

  1. ホームフォルダを分析 または ディスク全体を分析（/） を押します。ホームフォルダは数分かかる場合があります。
  2. フォルダの四角形をクリックすると、そのフォルダの中に入ります。上部のパス（パンくずリスト）をクリックすると、上位のフォルダに戻ります。
  3. 右側のリストには、現在のフォルダのサブフォルダとファイルがサイズ順に表示され、ターミナルで開いたり AIに質問 したりできます。
操作 動作
⌘ + ホイール 拡大・縮小
⌘ + ドラッグ 拡大したマップの移動
元のサイズ / マップ全体に戻る 拡大のリセット / 基準フォルダに戻る
  • 黄色の点線の枠は、整理候補に含まれているフォルダです。
  • iCloud などのクラウド同期フォルダと他のボリュームは、ファイルをダウンロードしないようにスキップし、スキップした一覧を別に表示します。
  • 1MB 未満のフォルダはまとめて計算します。分析結果は保存され、再分析 で新しく計算します。

大きなファイル

容量マップ → 大きなファイルで、大きなファイル・古いダウンロード・重複ダウンロードを選び、スキャンを押します。最小サイズは100MB・250MB・500MB・1GB・5GB、経過日数は30・90・180・365日から選べます。古いダウンロードは ~/Downloads の直下の項目が対象で、フォルダ内の最終更新も確認します。検索・並べ替え・キャンセルに対応しています。重複は1MB以上のファイルのサイズ、先頭64KB、全体のSHA-256で確認します。

個人ファイルは初期状態では未選択です。重複グループのみ、最も古い原本候補を残してコピーを選択します。件数・合計サイズ・一覧を確認してゴミ箱へ移動すると、直前にファイル情報を再確認します。Library・音楽データ・バンドル・リンク・別ボリューム・未ダウンロードのクラウド項目と、安全を確認できないフォルダは除外します。結果はメモリ内だけに保存します。アクセスが拒否された場合は、システム設定 → プライバシーとセキュリティ → ファイルとフォルダでTidemarkを許可し、再スキャンしてください。

AIツール

AIツールのディスク使用量、再ダウンロード可能なキャッシュ、実行中のAIプロセスのCPU・メモリ、対応するGPUの使用率を確認できます。ツールを展開するとキャッシュ・モデル・ユーザーデータ別のパスとサイズが表示され、Finderで表示で場所を開けます。ユーザーデータをキャッシュとして表示することはなく、この画面から削除やプロセス終了は行いません。

タブを初めて開くと保存済みの測定結果を表示し、記録がない場合のみ自動測定します。再測定とキャンセルを利用できます。プロセスはタブが表示されている間、約3秒ごとに更新され、一時停止できます。CPUはコア基準で100%を超える場合があり、RSSメモリは実際の使用量より小さい場合があります。共有データによりモデル別の合計が実際のディスク使用量を上回る場合があります。取得できないGPU情報は表示されません。

サーバー

TCPの待ち受けポートをプロセスごとに表示します。「更新」で再取得し、ポート・名前の検索やネットワーク公開のみの絞り込みができます。「このMacのみ」はループバック、「ネットワークに公開」は他の機器から到達し得るアドレスへのバインドを意味します（ファイアウォールの許可とは別です）。一般的なポート用途は参考情報です。

  • コマンドラインと親プロセスを展開してから「終了」を選び、確認します。開始時刻・実行ファイル・ユーザーが変わっていれば中止します。SIGTERM後は最大5秒待ち、残っている場合のみSIGKILLによる強制終了を別途確認します。未保存の作業が失われる可能性があります。
  • Tidemark自身と祖先、他のユーザー、macOS構成要素、Docker、管理サービスは直接終了できません。安全情報が不足している場合も終了ボタンは表示しません。
  • AirPlayレシーバーはシステム設定 › 一般 › AirDropとHandoffでオフにします。Dockerは表示された docker stop <名前> でコンテナを停止します。Homebrewのボタンは内蔵ターミナルで brew services stop <formula> を準備し、Enterを押すと実行します。
  • launchd管理項目は再起動する可能性があるためサービス設定で停止します。Ollama.appの子サーバーはメニューバーのOllamaを終了してください。開発監視プロセスがあれば確認画面で親も選択できますが、既定は子のみで、親の別の作業も停止する可能性があります。

AIに質問

すでにインストールして使っている AIエージェントの CLI に、いま表示している項目について質問できます。AI は削除できず、提案だけを行います。対応エージェント：Claude Code（claude）、Codex（codex）、Gemini CLI（gemini）、Cursor CLI（cursor-agent）、OpenCode（opencode）。

質問のしかた

  1. ヘッダー右端のきらめきアイコン、詳細パネルの AIに質問、または項目を選んだ後に下部バーの AIに質問 を押します。
  2. エージェントを選び、質問を入力します。画面に合ったおすすめの質問（例：「このフォルダはどのプログラムが作ったものですか？」）をクリックして入力することもできます。
  3. ターミナルで開始 を押すと、エージェントが内蔵ターミナルで実行されます。現在の画面と選択した項目の情報が一緒に渡され、会話中に画面や選択を変えると、その最新の状態を基準に回答します。

AI は Tidemark の表示言語で回答します。エージェントはお使いのコンピュータの CLI として実行されるため、ログインや料金は各 CLI の設定に従います。

AIレビューのバッジ

AI が項目をレビューすると、リストと詳細パネルに結果が残ります。

バッジ 意味
整理可能 削除しても問題ないという意見
確認後に整理 内容を確認してから削除するようにという意見
保持を推奨 残しておくようにという意見

詳細パネルの AIレビューカードには、根拠、クリーンアップ時に問題になりうる点、復元方法が併せて表示されます。あくまで AI の意見なので、クリーンアップするかどうかはご自身で判断してください。

AIのクリーンアップ提案

  • AI がクリーンアップを提案すると、画面上部に AIがN件のクリーンアップを提案しました という案内が表示されます。選択が自動で変わることはありません。
  • 確認 を押すと、提案された項目が確認ダイアログに入り、提案の理由を自分で確認したというチェックを入れるとクリーンアップできます。
  • AI はスキャンしたファイル内の文言にだまされることがあるため、項目はご自身で確認してください。不要であれば 無視 を押します。

ターミナルとショートカット

画面下部にターミナルが内蔵されており、項目を直接確認したり、AI エージェントやパッケージのアップグレードを実行したりできます。

  • ヘッダーのターミナルアイコンで開閉します。詳細パネルの ターミナル は、その項目のフォルダで新しいターミナルを開きます。
  • タブ行の + は同じフォルダで新しいターミナルを開き、タブの × はそのシェルを終了します。
  • ターミナルの上端をドラッグして高さを調整し、ダブルクリックすると既定の高さに戻ります。
ショートカット 動作
⌘F 現在の画面の検索欄に移動
Esc（検索欄で） 検索語を消去
⌘+ / ⌘- / ⌘0 画面の拡大 / 縮小 / 元のサイズ（ターミナルにカーソルがあっても動作）
⌘ + ホイール、⌘ + ドラッグ 容量マップの拡大、移動

Windows と Linux では ⌘ の代わりに Ctrl を使います。画面の倍率とターミナルの高さは保存され、次回起動時も維持されます。

設定

ヘッダーの歯車アイコンで開きます。変更した値はすぐに反映され、次回起動時も維持されます。

項目 選択肢 デフォルト
テーマ システム設定 / ライト / ダーク システム設定（macOS・Windows のライト・ダークモードに従う）
言語 システム設定 / 한국어 / English / 日本語 / 简体中文 システム設定（一覧にない言語の場合は英語）
AIエージェント エージェントごとの使用の有無、デフォルトのエージェント、実行ファイルのパス インストールされているものをすべて使用

メニューバーと自動再スキャン

  • メニューバーに表示は既定でオフです。有効にするとウインドウを閉じても動作を続けます。メニューには空き容量、前回のスキャン、整理可能な容量と、Tidemarkを開く・今すぐスキャン・終了を表示します。Dockアイコンは維持します。
  • ログイン時に起動は既定でオフで、macOS 13以降の署名済みアプリのみ利用できます。macOSの実際の状態を表示し、承認が必要ならシステム設定で許可してください。ログイン起動時、メニューバーモードが有効な場合だけウインドウを隠します。
  • 整理候補を自動で再スキャンは既定で手動、6時間・毎日・毎週を選べます。アプリの実行中で他の作業がなく、AC電源使用中のみ更新します。電源状態が不明ならスキップします。ファイルの削除や通知は行いません。

言語

  • 言語を変更すると、画面がすぐに再描画されます。すでに生成されたスキャンの警告とチェックの説明は、次回のスキャンから新しい言語で表示されます。
  • システム設定 は起動時のシステム言語に従います。macOS では システム設定 › 一般 › 言語と地域 の最初の優先言語です。

AIエージェント

  • Tidemark は、実行ファイルがあるかどうかと、--version が実行できるかどうかだけを確認します。再確認 で改めてチェックします。
  • PATH から見つからない場合は、パス欄に実行ファイルを直接入力し（例：/opt/homebrew/bin/claude）、適用 を押します。
  • ログインやモデル設定の問題は、ターミナルで実行 で CLI を直接起動して確認します。

スポンサー

設定画面下部の スポンサーになる から、Tidemark の開発を支援できます。

アプリの更新

自動確認は初期状態で有効です。起動時、前回から24時間経つとGitHubのバージョン情報ファイルだけを取得します。今すぐ確認も使えます。 更新を押すとダウンロードし、署名・公証・検査値の確認後にインストールして再起動で更新します。整理中は再起動できません。 保存場所や検証の問題で自動更新できない場合はリリースページを開くから直接取得してください。ユーザーデータは保持されます。

安全機能

Tidemark は削除する前に何が削除されるかを表示し、次の場合は削除しないか、もう一度確認します。

機能 内容
読み取り専用のスキャン スキャンは検索とサイズの計測だけを行います。クリーンアップは確認ダイアログを経た場合にのみ実行されます
保護されたパス ホーム、デスクトップ、書類、システムフォルダとその上位のパスは、削除を拒否します
公式クリーンアップコマンドを優先 npm cache clean、uv cache clean、docker system prune のように、ツールが提供する方法を優先して使います
リンク・他のボリューム シンボリックリンクをたどらず、他のファイルシステムにまたがりません。ハードリンクは一度だけ数え、共有容量を別に表示します
プロジェクトの判定ファイル package.json、Cargo.toml、pyvenv.cfg のようなファイルがあるフォルダだけを、プロジェクトのクリーンアップ対象にします
git の確認 コミットしていない変更とプッシュしていないコミットを表示します。git を呼び出すときは、リポジトリ設定にあるコマンド実行の経路（core.fsmonitor など）を無効にします
危険な項目への同意 危険な項目や AI の提案が含まれる場合は、確認ダイアログで別途チェックを入れないと実行されません
ゴミ箱 ゴミ箱に移動をオンにすると元に戻せます。アプリ削除のデフォルトの方法もゴミ箱（root 所有のアプリは管理者用の削除保管庫）です
パスのすり替え防止 macOS・Linux では、古いファイルの削除をフォルダハンドル基準（openat/unlinkat）で行います
クリーンアップ履歴 何をいつクリーンアップしたかを clean-log.jsonl に記録します

CLIの使い方

同じエンジンをターミナルコマンド tidemark としても使えます。clean は --yes を付けない限り計画を表示するだけで（dry-run）、何も削除しません。

インストール（リポジトリから）：cargo install --path crates/cli

コマンド 役割 主なオプション
tidemark scan クリーンアップ可能な項目をスキャン --root <フォルダ>、--no-projects、--no-rules、--min-mb <MB>（デフォルト 1）、--git-fetch、--json
tidemark clean 項目をクリーンアップ scan のオプション + --rule <id>（複数回指定可）、--max-risk safe|caution|danger、--unused-days <N>、--include-warned、--trash、--yes
tidemark rules 現在の OS に適用されるルールの一覧 —
tidemark map [フォルダ] フォルダ別の容量（デフォルト：ホームフォルダ、2階層まで） 基準フォルダ（例：/、~/Desktop）
tidemark apps インストール済みアプリの最終使用日・サイズ・残留ファイル --unused-days <N>、--no-apple、--json
tidemark outdated 新バージョンのあるグローバルパッケージ（Homebrew、npm、pnpm） — 
# スキャンのみ（何も削除しない）
tidemark scan

# 安全な項目のクリーンアップ計画を表示（dry-run）
tidemark clean --max-risk safe

# 90日以上使っていないプロジェクトの node_modules をゴミ箱へ
tidemark clean --rule project:node_modules --unused-days 90 --trash --yes

# 1つのルールだけを実際にクリーンアップ
tidemark clean --rule npm-cache --yes

出力言語は OS の言語に従い、TIDEMARK_LANG=en tidemark scan のように変更できます（ko、en、ja、zh）。ルールの id は tidemark rules で確認します。

ユーザー定義のクリーンアップルール

デフォルトのルールにないキャッシュを追加したり、デフォルトのルールを無効にしたりするには、rules.toml を作成します。場所は macOS の場合 ~/Library/Application Support/tidemark/rules.toml です（他の OS では <config_dir>/tidemark/rules.toml）。

  • 形式はデフォルトのルールファイル（crates/infra/rules/default.toml）と同じです。
  • 同じ id を使うとデフォルトのルールを上書きし、disabled = true でデフォルトのルールを無効にします。
  • 変更後は、再スキャンすると反映されます。ユーザールールの名前と説明は翻訳されず、記述したとおりに表示されます。
# 新しいルールを追加
[[rules]]
id = "my-tool-cache"
name = "My Tool キャッシュ"
category = "package_cache"
risk = "safe"
description = "my-tool がダウンロードしたファイルです。"
restore = "次回の実行時に再ダウンロードします。"
paths = { macos = ["~/Library/Caches/my-tool"], linux = ["~/.cache/my-tool"] }
mode = "contents"

# デフォルトのルールを無効にする（id、name、category、risk は常に必須）
[[rules]]
id = "yarn-cache"
name = "Yarn キャッシュ"
category = "package_cache"
risk = "safe"
disabled = true
フィールド 意味
id、name ルールの識別子と、画面に表示する名前。category、risk とともに必須
category package_cache、project_deps、build_cache、ai_tool、ai_model、ide、container、temp、logs、app_cache、trash
risk safe | caution | danger
paths all、unix、macos、linux、windows ごとのパス。~、$VAR、${VAR}、%VAR% を使用可能 プロファイル用の一階層の * のみ対応し、再帰的な ** や複数階層の * は非対応です。
paths.priority, paths.pointer, paths.first_existing priority は最初に展開できるパスを使います。pointer = { file, suffix } はファイル内のホームに suffix を追加し、first_existing = true は最初に存在する既定のフォルダを選びます。
mode whole（パスを削除） | contents（中身を削除） | children（サブ項目ごとに表示） | aged_files（古いファイルのみ）
min_age_days、include、exclude aged_files の日数とルート基準のglob、children の候補名のglob。contents の exclude はルート基準の子パスです。
command 公式クリーンアップコマンド { program, args }。指定するとまずこれを実行
fallback_delete コマンドがない、または失敗した場合に直接削除（デフォルト true）
inspect 実行前の解放量チェック：simctl-unavailable | docker-prune | brew-cleanup
partial コマンドが一部だけをクリーンアップする（表示される容量は最大値）
processes 実行中であれば警告するプロセス名

データの保存場所とトラブルシューティング

Tidemark のデータはすべてお使いのコンピュータにのみ保存され、macOS では ~/Library/Application Support/tidemark/ にあります。

ファイル 内容
last-scan.json 前回の整理候補のスキャン結果
apps.json インストール済みアプリ・グローバルパッケージのスキャン結果
disk-map.json 容量マップの分析結果
ai-reviews.json AIレビューの結果
ui.json テーマ、言語、画面の倍率、ターミナルの高さ、AIエージェントの設定
clean-log.jsonl クリーンアップ履歴
rules.toml ユーザー定義のクリーンアップルール（作成した場合のみ）

以前の名前（Storage Clear）の storage-clear フォルダがある場合は、初回起動時に自動で tidemark に移行されます。

よくある質問

クリーンアップしたのに空き容量が増えません。

  • ゴミ箱に移動 をオンにしてクリーンアップした場合は、ゴミ箱を空にする必要があります。管理者権限で削除したアプリは、保管庫を空にする を押す必要があります。
  • pnpm のストアのように、他の場所とハードリンクで共有されているファイルは、削除しても容量が増えません。リストには ハードリンク共有 と表示されます。
  • Time Machine のローカルスナップショットがある場合、macOS が表示する空き容量の増加が遅れることがあります。

AIに質問でエージェントが見つかりません。

Tidemark は起動時にログインシェルの PATH を取得して claude、codex を探します。それでも見つからない場合は、設定で実行ファイルのパスを直接指定してください。

言語を変更したのに、一部の文言が以前の言語で表示されます。

スキャンの警告、事前チェックの説明、git の状態メモは、スキャン時の言語で保存されます。再スキャン すると新しい言語に切り替わります。

スキャン結果が実際と異なります。

上部のステータス行の 前回のスキャン結果 · N日前 は、保存された結果を表示していることを意味します。クリーンアップの前に 再スキャン すると正確になります。

初めて開くときに「開発元を確認できない」と表示されて開けません。

まだ Apple の公証を受けていないビルドです。Finder でアプリを Control キーを押しながらクリック › 開く を選ぶと、一度許可した後はそのまま開けるようになります。
